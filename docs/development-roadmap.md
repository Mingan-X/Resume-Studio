# 开发计划

当前稳定基线包含API/空Worker、配置与HTTP边界、数据库迁移和基础设施诊断。以下计划按依赖顺序推进，未实现的目标不视为已交付能力。

## 1. 工程基线

已具备固定依赖和锁文件、ESM/装饰器编译、类型检查、Lint、Node测试、真实服务诊断与项目容器隔离。已有验证范围和限制见[测试文档](testing.md)，运行方式见[部署文档](deployment.md)。

## 2. 工作流持久化与观测

接入官方PostgreSQL Checkpointer及Langfuse，先用合成任务验证，暂不依赖真实简历或模型服务。

验收条件：

- 首次setup、重复初始化保护和Checkpoint表权限隔离通过。
- 确认旧执行及其写入已停止后，才从原thread恢复，已持久化成功产物不重复提交；覆盖有Checkpoint与首次Checkpoint不存在两种情况。
- 首Checkpoint不存在时可依据已保存的任务输入恢复，不能丢失已接收请求。
- 无法确认旧执行停止时，保留原taskId和输入快照，创建新恢复thread并通过业务fence隔离迟到写入。以真实Worker/PostgreSQL测试暂停旧执行、失去租约/锁、恢复旧执行：旧token不能写业务产物/终态，旧Checkpoint只能落在旧thread且不能污染新activeGraphThreadId。官方Checkpointer内部SQL不自动受业务fence约束，需单独验证thread隔离，不能只测普通重启或mock token。
- OTel/Langfuse版本真实编译并收到关联span，SDK与服务端兼容。
- 观测服务故障不导致业务失败；脱敏用例验证无合成秘密上报。

## 3. 业务实现顺序

| 能力 | 交付内容 | 验收要求 |
|---|---|---|
| 任务与消息可靠性 | AnalysisTask、JobIndexTask及共享OutboxEvent/Receipt/Attempt/Event、租约、查询、取消与恢复调度 | 两类任务共享交付/幂等/fencing机制但业务状态独立；Outbox支持不同业务聚合；publish及ACK窗口不丢任务/不重复产物；重试有界；网络分区/旧执行隔离；DLQ定位与受控重放 |
| 简历文件与证据 | Storage、上传、文字块与结构化简历 | PDF/DOCX正常、损坏、加密、扫描、双栏和表格样本；无任意路径读写；引用逐字可核对；空文本不成功；多任务不串数据 |
| JD与rubric | JD入库/结构化、要求确认、不可变版本、JobIndexTask调度、六维标准 | 要求来源可追踪；硬门槛和权重确认后才发布；发布版本/索引任务/Outbox在同事务持久化；旧索引执行不能更新新版本READY状态；所有权检查 |
| 岗位召回 | 技能关键词、Qdrant索引、Dense Vector与RRF融合、CandidateSet | 至少100条合成JD；索引幂等；旧版本不混入；维数变化新collection；中文技能相关性标注；失败显式降级 |
| 六维画像与语义匹配 | Profile/Matching节点、结构化判断、预算与部分失败 | 六维仅作辅助上下文；逐要求基于证据判断；unknown不伪装低分；每条计划精判要求有结果或未完成状态；400条默认预算超限返回截断/未完成数量；模型不输出总分；拒绝伪造/越界引用；并发受限 |
| 确定性评分与排名 | 纯函数计算、冻结判断、Top10及调权重算 | 固定输入重复100次一致；缺失/负/NaN/Infinity/零总权重/重复ID/不支持维度/同分/unknown边界；重算无模型调用；原候选第11名可进入新榜单；不足10不补造 |
| 报告与前端 | 前端框架、证据展开、真实进度、不可变报告历史 | 报告关联输入/候选/画像与匹配判断/Rubric/评分版本；刷新/断网/重启仍可查；partial显示覆盖率；SSE按seq补读；前端不自行计算最终分 |
| 质量与发布 | 合成或经过授权脱敏的标注评测集、预算/性能数据、部署与运维 | 至少20份简历及100–300 JD的目标集；人工标注质量评估；权限/删除链路；故障注入；备份恢复；依赖审计；实测时延目标 |

模型评测关注引用有效率、结构化正确率、unknown合理性、逐要求判断质量、Recall@K/推荐相关性和费用，而不只判断“输出非空”。上线阈值须依据标注数据确定，不预先宣称准确率。

任务与消息基础设施先支持两种任务契约和隔离测试，再按上述顺序接入JD索引业务，不提前实现岗位或简历功能。恢复/重试保持原任务身份与冻结输入；重新分析/重新召回创建新AnalysisTask和报告，不覆盖历史。NodeArtifact的operationKey需覆盖输入、组件/Schema及适用的prompt/model等版本，并以jobVersionId及必要的requirementId/batchId区分并行分支。

文件安全验收包含解压总量/条目数、异常压缩结构、路径穿越及CPU/内存/总耗时上限。扫描PDF样本用于检测并明确拒绝或提示未支持，首版默认不承诺OCR；是否纳入MVP须依据质量、成本和隐私实验单独确认。

文档中的并发数、超时、重试、租约和400条默认判断预算为待验证参数，不是生产级保证；数据量与时延是评测目标，模型、Embedding、前端及OCR决策仍保持待定。

## 4. 变更验收

每项实现说明输入、输出、调用链和故障边界；类型检查、Lint与相关测试通过后进行代码审查与维护者验收。未运行项、服务故障和限制明确记录，不能以元数据范围匹配替代真实运行。分支流程见[CONTRIBUTING](../CONTRIBUTING.md)。
